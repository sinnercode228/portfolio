# Telegram-бот для заявок на aiogram 3

Бот собирает заявки через анкету из четырёх шагов, сохраняет их в SQLite и присылает карточку в админ-чаты. У администратора есть `/leads`, `/export` в CSV, `/stats` и `/broadcast`. Написан на Python 3.11+ и aiogram 3 (long polling, FSM, CallbackData), с базой работает через aiosqlite. Студия «Ромашка Digital» существует только в [`texts.py`](bot/texts.py), вместе со своими услугами и ценами.

Кусок вывода [`scripts/demo_dialog.py`](scripts/demo_dialog.py). Скрипт прогоняет настоящие хендлеры на том же фейковом Telegram, что и тесты, без токена и интернета. Часть сообщений и строк пропущена, эмодзи убраны:

```text
Анна: 8 900 12
бот → Анна:
   Не получилось распознать номер
   Введите его в формате +7 900 123-45-67 или нажмите «Отправить мой номер».
Анна: 8 (900) 123-45-67
бот → Анна:
   Номер сохранён: +7 (900) 123-45-67
...
Анна нажимает [Отправить]
бот → Анна:
   Спасибо, Анна! Заявка №1 принята.
бот → Админ:
   Заявка №1 · 26.09.2026 16:38
   Анна
   +7 (900) 123-45-67
   Лендинг
   Статус: Новая
   [В работе]  [Закрыта]  [Отклонена]
```

Если на экране подтверждения поправить одно поле, бот сразу возвращается к подтверждению. Хендлер поля видит в данных анкеты `editing=True` и пропускает оставшиеся шаги, порядок которых задан словарём `NEXT_STEP` в [`handlers/form.py`](bot/handlers/form.py).

## Двойное «Отправить» и нажатия после простоя

Два быстрых нажатия «Отправить» дают одну заявку. Диспетчер собран с `SimpleEventIsolation` ([`app.py`](bot/app.py)), поэтому апдейты одного пользователя обрабатываются по очереди. `confirm_submit` снимает состояние анкеты до записи в базу, и второе нажатие, не пройдя фильтр `LeadForm.confirm`, получает «Эта кнопка устарела». Если запись падает, состояние возвращается, и ту же анкету можно отправить ещё раз.

Карточка админам уходит только после записи, в каждый чат отдельно ([`notify.py`](bot/services/notify.py)). Недоступная админ-группа не мешает ответить клиенту, а сбой ответа клиенту не мешает отправить карточку, оба случая есть в [`test_user_flow.py`](tests/test_user_flow.py).

Пока бот выключен, нажатия кнопок копятся у Telegram и после запуска приходят протухшими, и `answerCallbackQuery` отвечает на них «query is too old». `ack()` в [`handlers/utils.py`](bot/handlers/utils.py) пишет эту ошибку в debug-лог и не прерывает хендлер, так что кнопки меню и статусов заявки срабатывают. `test_expired_callback_query_still_works` подсовывает эту ошибку при нажатии «Отправить» и проверяет, что заявка сохранилась.

## Номер, рассылка и выгрузка в CSV

Телефон приводит к E.164 чистая функция `normalize_phone` из [`validators.py`](bot/validators.py), через неё же проходит присланный контакт, а контакт с чужим `user_id` бот не принимает. Без «+» ведущая 8 в 11-значном номере меняется на 7, к десяти цифрам на 3, 4, 7, 8 или 9 дописывается 7, и `(495) 123-45-67` становится `+74951234567`.

Рассылка копирует сообщение (`copy_message`) активным пользователям по одному с паузой 0,05 с, не больше 20 сообщений в секунду ([`broadcast.py`](bot/services/broadcast.py)). На `TelegramRetryAfter` бот ждёт, сколько сказал Telegram, и повторяет один раз. Кто заблокировал бота или удалил аккаунт (`TelegramForbiddenError`, `TelegramNotFound`), получает флаг `is_blocked` и выпадает из рассылок, пока не вернётся через `/start`, новую заявку или разблокировку. Сама рассылка идёт фоновой задачей, и [`tasks.py`](bot/services/tasks.py) держит ссылки на задачи в `set`, чтобы сборщик мусора не прервал её на середине.

`/export` отдаёт CSV под Excel с русской локалью: UTF-8 с BOM, разделитель «;», переводы строк CRLF. `sanitize_cell` в [`export.py`](bot/export.py) ставит апостроф перед значением, которое начинается с `=`, `+`, `-`, `@`, табуляции или `\r`, и `=HYPERLINK(...)` в комментарии остаётся текстом. Username по той же причине пишется без «@».

Недозаполненная анкета после перезапуска теряется, потому что FSM хранится в `MemoryStorage`, а прогресс рассылки нигде не записывается, и прерванный `/broadcast` при повторе уйдёт всем активным пользователям заново.

## Docker и systemd

`docker compose up -d --build` собирает образ из [`Dockerfile`](Dockerfile) и запускает бота от `botuser` с uid 10001, база лежит в томе `bot-data` ([`docker-compose.yml`](docker-compose.yml)). Для VPS без Docker есть unit [`deploy/romashka-bot.service`](deploy/romashka-bot.service) с песочницей (`NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome`, `PrivateTmp`, `ReadWritePaths` только на `/opt/romashka-bot/data`) и `RestartPreventExitStatus=2`: если конфиг не проходит проверку при старте, `python -m bot` выходит с кодом 2, и systemd не перезапускает его по кругу.

## Демо в терминале и живой бот

```bash
git clone https://github.com/sinnercode228/portfolio.git
cd portfolio/telegram-bot-demo
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python scripts/demo_dialog.py   # диалог из примера выше
cp .env.example .env            # вписать BOT_TOKEN от @BotFather
python -m bot
```

Переменные с комментариями лежат в [`.env.example`](.env.example), обязательна только `BOT_TOKEN`. `ADMIN_IDS` задаёт, кому доступны админ-команды и кнопки статусов (свой ID бот покажет по `/id`), `ADMIN_CHAT_IDS` задаёт чаты для карточек, по умолчанию это те же `ADMIN_IDS`.

## Тесты на FakeSession

```bash
pip install -r requirements-dev.txt
pytest
ruff check . && ruff format --check .
```

139 тестов прогоняют диалоги через настоящий диспетчер aiogram поверх [`FakeSession`](tests/fakes.py). Она записывает каждый вызов Bot API и отвечает локально, а тест проверяет, какие сообщения и кнопки ушли и что легло в базу.
