# Telegram-бот для заявок на aiogram 3

Бот собирает заявки через анкету из четырёх шагов, сохраняет их в SQLite и присылает карточку в админ-чаты. У администратора есть `/leads`, `/export` в CSV, `/stats` и `/broadcast`. Код написан на Python 3.11+ и aiogram 3 (long polling, FSM, CallbackData), с базой работает через aiosqlite. Студия «Ромашка Digital» существует только в [`texts.py`](bot/texts.py), вместе со своими услугами и ценами.

Кусок вывода [`scripts/demo_dialog.py`](scripts/demo_dialog.py). Скрипт прогоняет настоящие хендлеры на том же фейковом Telegram, что и тесты, без токена и интернета. Часть сообщений и строк пропущена, эмодзи убраны или заменены словами:

```text
Анна: 8 900 12
бот → Анна:
   Не получилось распознать номер
   Введите его в формате +7 900 123-45-67 или нажмите «Отправить мой номер».
Анна: 8 (900) 123-45-67
бот → Анна:
   Номер сохранён: +7 (900) 123-45-67
...
Анна нажимает [Отправить]
бот → Анна:
   Спасибо, Анна! Заявка №1 принята.
бот → Админ:
   Заявка №1 · 26.09.2026 16:38
   Анна
   +7 (900) 123-45-67
   Лендинг
   Статус: Новая
   [В работе]  [Закрыта]  [Отклонена]
```

Телефон приводит к E.164 чистая функция `normalize_phone` из [`validators.py`](bot/validators.py): без «+» ведущая 8 в 11-значном номере меняется на 7, а к десятизначному номеру, начинающемуся на 3, 4, 7, 8 или 9, спереди дописывается 7, и `(495) 123-45-67` становится `+74951234567`. Присланный контакт проходит через ту же функцию, а контакт с чужим `user_id` бот отклоняет.

Если на экране подтверждения поправить одно поле, бот сразу возвращается к подтверждению. Хендлер поля видит в данных анкеты `editing=True` и пропускает оставшиеся шаги, порядок которых задан словарём `NEXT_STEP` в [`handlers/form.py`](bot/handlers/form.py).

## Двойное «Отправить» и нажатия после простоя

Два быстрых нажатия «Отправить» дают одну заявку. Диспетчер собран с `SimpleEventIsolation` ([`app.py`](bot/app.py)), поэтому апдейты одного пользователя обрабатываются по очереди. `confirm_submit` снимает состояние анкеты до записи в базу, и второе нажатие, не пройдя фильтр `LeadForm.confirm`, получает «Эта кнопка устарела». Если запись падает, состояние возвращается, и ту же анкету можно отправить ещё раз.

Карточка админам уходит только после записи, в каждый чат отдельно ([`notify.py`](bot/services/notify.py)). Если бота удалили из админ-группы, клиент всё равно получает подтверждение, а карточка приходит в остальные админ-чаты. Когда не доходит ответ клиенту, карточка админам уходит как обычно. Оба случая проверяются в [`test_user_flow.py`](tests/test_user_flow.py).

Пока бот выключен, нажатия кнопок копятся у Telegram и после запуска приходят протухшими, и `answerCallbackQuery` отвечает на них «query is too old». `ack()` в [`handlers/utils.py`](bot/handlers/utils.py) пишет эту ошибку в debug-лог и не прерывает хендлер, так что кнопки меню и статусов заявки срабатывают. `test_expired_callback_query_still_works` подсовывает эту ошибку при нажатии «Отправить» в анкете, которая ещё в памяти, и проверяет, что заявка сохранилась.

## Команды администратора

Рассылка копирует сообщение (`copy_message`) активным пользователям по одному с паузой 0,05 с, не больше 20 сообщений в секунду ([`broadcast.py`](bot/services/broadcast.py)). На `TelegramRetryAfter` бот ждёт, сколько сказал Telegram, и повторяет один раз. Кто заблокировал бота или удалил аккаунт (`TelegramForbiddenError`, `TelegramNotFound`), получает флаг `is_blocked` и выпадает из рассылок, пока не вернётся через `/start`, новую заявку или разблокировку. Сама рассылка идёт фоновой задачей, и [`tasks.py`](bot/services/tasks.py) держит ссылки на задачи в `set`, чтобы сборщик мусора не прервал её на середине.

`/export` отдаёт CSV под Excel с русской локалью: UTF-8 с BOM, разделитель «;», переводы строк CRLF. `sanitize_cell` в [`export.py`](bot/export.py) ставит апостроф перед значением, которое начинается с `=`, `+`, `-`, `@`, табуляции или `\r`, и `=HYPERLINK(...)` в комментарии остаётся текстом. Username по той же причине пишется без «@».

## Из терминала в Telegram

```bash
git clone https://github.com/sinnercode228/portfolio.git
cd portfolio/telegram-bot-demo
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python scripts/demo_dialog.py   # диалог из примера выше
cp .env.example .env            # вписать BOT_TOKEN от @BotFather
python -m bot
```

Переменные с комментариями лежат в [`.env.example`](.env.example), обязательна только `BOT_TOKEN`. `ADMIN_IDS` задаёт, кому доступны админ-команды и кнопки статусов (свой ID бот покажет по `/id`). Карточки уходят в `ADMIN_CHAT_IDS`, а если переменная пустая, в личку тем же `ADMIN_IDS`.

## Деплой на VPS

С заполненным `.env` команда `docker compose up -d --build` собирает образ из [`Dockerfile`](Dockerfile) и запускает бота от `botuser` с uid 10001, база лежит в томе `bot-data`. Если Docker Hub недоступен, базовый образ меняется переменной `PYTHON_IMAGE` (пример с зеркалом есть в [`docker-compose.yml`](docker-compose.yml)).

Без Docker бота запускает unit [`deploy/romashka-bot.service`](deploy/romashka-bot.service). Он ждёт содержимое этой папки в `/opt/romashka-bot` вместе с `.venv` и `.env`, работает от системного пользователя `botuser` и включается `systemctl enable --now romashka-bot` после копирования в `/etc/systemd/system/`. `RestartPreventExitStatus=2` не даёт systemd перезапускать бота по кругу, когда конфиг не прошёл проверку при старте и `python -m bot` вышел с кодом 2. Песочницу задают `NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome` и `PrivateTmp`, а из постоянных путей на запись сервису открыт только `/opt/romashka-bot/data` (`ReadWritePaths`).

После перезапуска недозаполненная анкета теряется (FSM живёт в `MemoryStorage`), а прогресс рассылки нигде не записывается, так что прерванный `/broadcast` при повторе уйдёт всем активным пользователям заново.

## Тесты на FakeSession

```bash
pip install -r requirements-dev.txt
pytest && ruff check . && ruff format --check .
```

Тестов 139. Диалоговые сценарии в [`test_user_flow.py`](tests/test_user_flow.py) и [`test_admin.py`](tests/test_admin.py) идут через настоящий диспетчер aiogram поверх [`FakeSession`](tests/fakes.py). Она записывает каждый вызов Bot API и отвечает локально, а тест проверяет, какие сообщения и кнопки ушли и что легло в базу. Остальные файлы проверяют по отдельности валидаторы, конфиг, базу, форматирование, экспорт в CSV, фоновые задачи и запуск `python -m bot`.
